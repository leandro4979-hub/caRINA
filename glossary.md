# Glossary

Definitions for foundational software-development terms.

## A

### Algorithm

A finite, ordered sequence of unambiguous instructions designed to solve a problem or perform a computation.

### API — Application Programming Interface

A defined set of rules through which one software component communicates with another.

### Architecture

The high-level structural design of a software system: its major components, responsibilities, relationships, and governing principles.

### Asynchronous operation

An operation that begins without requiring its caller to wait for completion; its result is delivered later through a callback, promise, event, or task.

## B

### Backend

The server-side portion of an application responsible for business logic, data processing, authentication, integrations, and persistent storage.

### Branch

An independent line of development in a version-control repository.

### Bug

A defect that causes a program to produce an incorrect result, behave unpredictably, or fail to meet its requirements.

## C

### Cache

A temporary storage layer that retains frequently accessed data so later requests can be fulfilled more quickly.

### CI/CD — Continuous Integration and Continuous Delivery/Deployment

Practices that automate the integration, testing, validation, and release of software changes.

### Commit

A recorded snapshot of changes in a version-control system.

### Container

A lightweight, isolated runtime environment that packages an application with its dependencies and configuration.

## D

### Database

An organized collection of data designed for efficient storage, retrieval, modification, and administration.

### Debugging

The systematic process of identifying, isolating, and correcting defects in a program.

### Dependency

A component, library, service, package, or system required by another component to function as intended.

### Deployment

The process of making an application or update available in a target environment.

## F

### Framework

A reusable software foundation that provides conventions, libraries, and structural guidance for building applications.

### Frontend

The client-side portion of an application with which users directly interact.

### Function

A named, reusable unit of code that accepts zero or more inputs, performs a defined operation, and may return an output.

## G

### Git

A distributed version-control system that records changes to files over time.

### GitHub

A platform for hosting Git repositories and supporting collaborative development through pull requests, issues, reviews, automation, and documentation.

## M

### Markdown

A lightweight markup language that uses plain-text notation to format documents.

### Merge

The version-control process of combining changes from one branch or line of development into another.

## P

### Pull request

A proposed set of changes submitted for discussion, review, testing, and eventual merging into a shared codebase.

## R

### README

A primary introductory document for a project or repository, typically covering purpose, installation, usage, configuration, contribution, and licensing.

### Refactoring

Restructuring existing code without intentionally changing its externally observable behavior.

### Repository

A managed collection of project files and their revision history.

## T

### Testing

The process of evaluating software to determine whether it satisfies requirements and behaves as expected.

### Token

A discrete unit recognized during lexical analysis of source code; in security contexts, a credential used for authorization.

## V

### Version control

A system for recording and managing changes to files over time.

## W

### Webhook

A mechanism through which one system automatically sends an HTTP request to another when a specified event occurs.

### Workflow

A repeatable sequence of steps used to complete a process.
